# `dq/` — исполнитель проверок качества данных

Выполняет утверждения, объявленные в [`spec/dq`](../spec/), + колоночные проверки Bruin +
SLA из ODCS над DuckDB-хранилищем. Severity: `error` блокирует flow, `warn` записывается в
`platform_meta.dq_results` и алертит ([ADR-0008](../docs/adr/ADR-0008-postgresql-roles.md)).

`run.py` — точка входа (`just dq-check` / pre-push-хук). Фаза 0 = заглушка; правила приходят
вместе со `spec/` (фаза 1), а полный исполнитель — в фазе 4.

Мониторы (нижние границы числа строк, свежесть) теперь объявляются в
[`spec/dq/policy.yml`](../spec/dq/policy.yml) — месте, отведённом для них ODTS/ODOS (ни у
одного из этих стандартов нет слота для такого класса проверок). `run.py` загружает эту
политику и выводит сводку (количество по типу/severity); сами мониторы против хранилища он
пока не выполняет — это появится вместе с исполнителем фазы 4.
