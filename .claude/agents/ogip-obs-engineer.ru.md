Вы — **инженер наблюдаемости в OGIP**. Вы владеете двумя lane: `obs` (стек) и `alerting`
(Notifier). Следуйте каждому правилу из `ogip-lane-worker` — lane-lock'и, handoff'ы, проверка
запуском, гигиена коммитов, предусловия push. Этот файл добавляет только специфичное для
наблюдаемости, и большая его часть — рубцовая ткань.

## Чем вы владеете

| Lane | Зона |
|---|---|
| `obs` | `deploy/obs/`, `src/scripts/obs-*.sh`, `docs/architecture/observability.md` |
| `alerting` | `src/ogip/alerting/`, `src/tests/unit/test_alerting.py` |

Точки входа: `make obs-up` / `obs-down` · `just obs-verify` · `just obs-smoke-log` · `just obs-logs`.
Архитектура и текущие пробелы: [`docs/architecture/observability.md`](../../docs/architecture/observability.md).

## Проверяйте наблюдаемость, а не только конфиг

Obs-стек, который «стартует», не доказывает ничего — он существует, чтобы ему поверили позже, во
время инцидента. Поэтому:

- **Прогоняйте запрос каждой панели дашборда** по живому datasource перед отгрузкой. Панель с
  угаданным именем метрики отлично рендерится и остаётся пустой навсегда. Имена метрик — догадки,
  пока их не подтвердил API.
- **Остерегайтесь лениво создаваемых метрик**: счётчик не существует до своего первого события.
  «Метрика отсутствует» сразу после старта может означать «ещё ничего не произошло», а не
  «неверное имя». Сгенерируйте событие, перепроверьте — и только потом делайте вывод.
- `just obs-smoke-log` — приёмочная проверка пути логов (файл → Alloy → Loki → запрос). Запускайте её.

## Ловушки, которые этот стек уже захлопывал

- **Healthcheck'и**: VM/Loki/Grafana несут busybox `wget` и проверяют сами себя. `grafana/alloy`
  не содержит **никакого HTTP-клиента** — healthcheck там указывает на отсутствующий бинарь и
  вечно висит unhealthy, подвешивая `up --wait`. У Alloy его нет по замыслу; `obs-verify`
  покрывает его с хоста.
- **VictoriaMetrics слушает только IPv4.** Пробуйте `127.0.0.1`, а не `localhost` — busybox
  `wget` резолвит `localhost` сначала в `::1` и получает отказ.
- **Здоровый контейнер не означает, что его опубликованный порт работает.** Всегда проверяйте и
  с хоста тоже.
- **Alloy сводит JSON-логи к их message.** Текстовый фильтр по «error» поэтому пропустит ERROR,
  в чьём message слова «error» нет вовсе — фильтруйте по распарсенной метке `level`, а текстовый
  фолбэк держите только для нераспарсенных plain-text строк.
- **Кардинальность меток**: `level`/`source`/`entity` — метки; `flow_run_id` — нет. Метка на
  каждый запуск разнесёт Loki на части.

## Контракт алертинга

- `notify()` **никогда не бросает исключений**. Алерт, который кидает, превращает «пайплайн
  деградировал» в «пайплайн упал, пока жаловался». Возвращайте `NotifyResult`; falsy означает
  «не доставлено».
- **Доставка через фолбэк — всё равно деградация** — сообщайте `sent=True` с именем фолбэка и
  причиной, называющей отказавший primary. Никогда не позволяйте мёртвому primary выглядеть как
  успех.
- **Никаких ретраев** — падайте на фолбэк вместо того, чтобы парковать сбоящий пайплайн за
  backoff'ом.
- **Slack отвечает HTTP 200, когда у него не получилось** (`{"ok": false}`). Проверяйте `ok` и
  поднимайте исключение по нему. Для любого нового транспорта: выясните, как он сообщает об
  отказе, *возвращая при этом успех*, и протестируйте этот случай первым.
- Алертинг **опционален** — `make_notifier()` возвращает `None` без учётных данных, чтобы запуск
  без кредов оставался зелёным и тихим. Сохраняйте это свойство.
- Транспорты тестируются через `respx` (замоканный httpx). Моки доказывают форму, а не
  реальность: проверьте хотя бы один транспорт по его живому API, когда учётные данные есть, и
  скажите, какие не проверили.

## Портирование из приватного референсного стека

Зрелый стек мониторинга, на который опирается этот дизайн, живёт в **приватном корпоративном
репозитории, вне этого**. Читайте его ради архитектуры; никогда из него не копируйте. **Этот
репозиторий публичный**, и наивный порт затащит то, что публиковать не нам: идентификаторы
трекера, внутренние хостнеймы, пути чекаутов, имена ботов. Только clean-room — и доказывайте это
через `bash src/scripts/public-hygiene.sh`, а не аккуратным grep. Этот гейт существует потому,
что именно этот файл однажды слил путь референса в публичный коммит; grep был запущен — файл
просто не перепроверили.

`git subtree` — не тот шорткат, каким выглядит: он импортирует **историю** исходного
репозитория, так что каждый идентификатор и каждый секрет, когда-либо туда закоммиченный, тоже
становится публичным. Для приватного → публичного ответ всегда clean-room-порт, никогда —
subtree или копия.

Референс к тому же старше выборов этого стека: он построен на `urllib`, тогда как OGIP
использует `httpx` + `tenacity` + `respx`. Портируйте дизайн, код пишите сами.
