# `/add-data-source` — Предложение по декомпозиции навыка

> **Status: PROPOSAL — gated.** Этот документ не создаёт никакого навыка. Создание идёт через
> `/propose-skill-for-that` → `/create-skill` → `/save-all-deterministic-for-skill-as-scripts`
> согласно действующей политике создания навыков (файлы навыков никогда не пишутся вручную).

**Цель:** превратить `/add-data-source` из 243-строчного монолита в цепочку, члены которой
вызываются по отдельности, и закрыть четыре пробела в возможностях, которые каталог не покрывает.

**Метод:** `/split-skill-on-subskills` шаги 1–3 (определить → аудит на перекрытие → решить форму
разбиения). Шаги 4–6 (создать → рефакторить родителя → синхронизировать) — это gated-часть.

---

## 1. Аудит: что уже существует

Просмотрены все 521 навыков каталога. **Переиспользование побеждает создание в шести из
запрошенных областей.**

| Запрошенная возможность | Существующий навык | Вердикт |
|---|---|---|
| Upsert ODCS для источника | **`/generate-odcs-specs`** (`de/contracts/`) | **REUSE.** Полноценный навык авторинга ODCS v3 уже существует, и он уже именует `spec/contracts/<source>/<name>.odcs.yaml` и контракт Layer-0 `<system>__<table>`. Создавать нечего. |
| Исследование источника + маршрутизация к движку | **`/find-sources-and-match-tool`** (`de/ingestion/`) | **REUSE.** Уже извлечённые Шаги 0–2 родителя, с 8-вердиктным маршрутизатором. |
| dlt «Prefect-related» | **`/integrate-sql-tool-with-prefect`** | **PARTIAL** — покрывает пер-движковые *transform*-потоки, а не ingestion. Переиспользуйте паттерн flow/asset, не повторяйте его. |
| dlt «Dagster-related» | **`/add-dagster-module`**, `/add-dagster-odp-module`, `/integrate-dagster-with-dbt` | **PARTIAL** — та же форма. |
| dlt под Dagster под Prefect | **`/call-dagster-from-prefect`** | **REUSE** дословно. |
| SQL staging-модели | **`/generate-agnostic-bruin-sql-specs`**, `/spec-compile-engines` | **REUSE.** |
| Запуск e2e и отгрузка по зелёному | **`/e2e-ship`**, `/dagster-e2e-run` | **REUSE.** |
| Доказать, что тест/gate реально падает | **`/verify-gate-actually-covers`** | **REUSE** — это ответ на «реальный ли мой новый CI-gate». |
| Бизнес-описание / потенциал прибыли | — | **GAP** |
| Дизайн пайплайна источник → landing → staging | — | **GAP** |
| Генерация синтетических данных | — | **GAP** — ноль попаданий по `synthetic data\|fixture generat\|mock data\|faker` по всем 521 навыкам |
| Пер-движковый авторинг коннекторов | — | **GAP** — маршрутизатор *решает* инструмент; ничто не *реализует* по инструменту |
| Авторинг + отладка пер-стадийных тестов, привязка к CI | — | **GAP** (частично покрыто по краям двумя строками REUSE выше) |

### Единственное место, где буквальную просьбу следует отклонить

Просьба запрашивает пять dlt-навыков: *native / standalone / Dagster-related / OpenDBT-related /
Prefect-related*. **Рекомендуем один `/write-ingestion-dlt` вместо этого**, потому что эти пять —
две разные оси под одним именем:

- *native vs standalone* — это ось **упаковки** — тот же код `dlt.resource`/`dlt.pipeline`, разная
  точка входа.
- *Dagster / OpenDBT / Prefect* — это ось **хостинга**, и `de/orchestration/` уже владеет ею в
  четырёх навыках.

Пять dlt-навыков каждый повторял бы один и тот же авторинг resource-and-pipeline, затем разошлись бы —
ровно тот guardrail из `split-skill-on-subskills` *«не оставляйте провайдер-специфичную логику
продублированной и в родителе, и в субнавыке»*. Один dlt-навык с секцией **«где он работает»**,
которая делегирует по имени существующим навыкам оркестрации, несёт ту же информацию и имеет одно
место для правок.

Пер-движковое разбиение **оправдано** между *разными* движками: `RESTAPIConfig` у dlt,
CLI-вызов ingestr, конфигурация коннектора Airbyte и вежливость/контракт JSON-LD скрейпера не
разделяют по сути ничего. Это реальное расхождение, а не дублирование.

## 2. Предлагаемая форма разбиения

**Разрез следует собственному словарю маршрутизатора.** `/find-sources-and-match-tool` уже выдаёт
один из восьми вердиктов (`dlt · ingestr · airbyte · scraping · complex_api · spark · gcp · none`).
Один реализатор на *живой* вердикт делает границу принципиальной, а не вкусовой, и делает
маршрутизацию исполнимой сквозь: `route <key>` называет навык, который его строит.

`spark` и `gcp` зарезервированы без прецедента в реестре; `none` означает FORBIDDEN. **Никаких
навыков для этих трёх** — три навыка, которые ничто не вызвало бы.

### Новые навыки — всего 10, в трёх волнах

#### Волна 1 — пробелы, блокирующие OGIP сегодня (3)

| Slug | Область | Назначение | Почему это не секция родителя |
|---|---|---|---|
| `describe-source-business-value` | `de/ingestion` | Бизнес-описание, сценарии использования, потенциал прибыли и **какое измерение модели раскрывает источник**. Пишет блок `business:` в запись реестра и строку в `docs/domain/sources.md`. | Вызывается *до* любого кода, часто для источников, которые никогда не строятся. Отвечает на «стоит ли?», что родитель считает уже решённым. |
| `design-source-pipeline` | `de/ingestion` | Дизайн источник → landing → raw → staging, **плюс пер-стадийный план тестов**: против чего должна тестироваться каждая стадия и какие фикстуры ей нужны. Производит дизайн, который потребляют навыки-реализаторы. | Здесь *отвечаются* вопросы синтетических данных; генерация — отдельный, более поздний шаг. Дизайн переживает любой один выбор движка. |
| `generate-synthetic-fixtures` | `de/testing` *(новая область)* | Детерминированные, **контракт-ориентированные** фикстуры, генерируемые из контракта ODCS — seeded, без рантайм-случайности в закоммиченных файлах. Обеспечивает закон размера фикстур/LFS. | Ноль покрытия в каталоге, и полезно далеко за пределами ingestion (transform, DQ, e2e — всем нужно). |

#### Волна 2 — реализаторы, один на живой вердикт маршрутизатора (5)

`write-ingestion-dlt` · `write-ingestion-ingestr` · `write-ingestion-airbyte-oss` ·
`write-ingestion-scraping` · `write-ingestion-complex-api`

Каждый берёт прозондированный + маршрутизированный + законтрактованный источник и производит
коннектор. В каждый входят **только** через его вердикт маршрутизатора. Общие законы (Layer-0,
SSoT-конфиг, размер фикстур/LFS) остаются в родителе и на них ссылаются, никогда не копируют —
родитель остаётся единственным местом, где они изложены.

`write-ingestion-dlt` дополнительно несёт секцию **«где он работает»**: standalone-скрипт ·
Dagster-ассет (`/add-dagster-module`) · Prefect-поток (`/integrate-sql-tool-with-prefect`) ·
Dagster-внутри-Prefect (`/call-dagster-from-prefect`). Делегирование по имени, без повторов.

#### Волна 3 — тесты и цепочка (2)

| Slug | Область | Назначение |
|---|---|---|
| `author-pipeline-stage-tests` | `de/testing` | Создать / запустить / **отладить** пер-стадийные юнит-тесты и финальный e2e, затем привязать их к CI. Передаёт вопрос «реально ли этот gate падает на настоящем дефекте» в `/verify-gate-actually-covers`, а не выводит его заново. |
| `onboard-data-source` | `de/ingestion` | **Цепочка / оркестрирующий навык.** business → find+route → ODCS → design → implement(verdict) → fixtures → tests → CI → ship. Одна команда заменяет знание девяти навыков и их порядка. |

**Волна 3 должна идти последней.** Оркестрирующий навык, называющий навыки, которых ещё не
существует, — сломанный навык, читающийся как рабочий.

### Чем становится `/add-data-source`

Не удалён, не зонтик. Он сохраняет: предусловия (lane-lock, прочитать правила цели), Шаг 0
(уже собран?), Шаг 3 (**gate легальности — блокирующий, и он не должен сдвигаться**), три
закона, Definition of Done и Шаг 6 (ship). Он **делегирует** Шаги 1–2 (уже извлечены),
авторинг контракта (`/generate-odcs-specs`), дизайн, реализацию, фикстуры и тесты.

Он становится членом *scaffold-and-ship* цепочки `onboard-data-source` — тем, чем он на самом
деле является сегодня, минус части, которые он инлайнит.

## 3. Скрипты, а не навыки

Согласно действующему предпочтению скрипта перед навыком везде, где шаг детерминирован:

| Потребность | Вердикт |
|---|---|
| Принуждение Definition-of-Done | **Скрипт** — `.ci/steps/source-dod.sh`, уже полностью специфицирован в родственном плане `2026-07-20-source-dod-registry-and-domain-docs.md` Task 2. Не делайте его ещё и навыком. |
| Валидация блока `business:` в реестре | **Расширить существующий скрипт** — добавить проверку поля в `just -f "$JF" split-check`. Никакого нового артефакта. |
| Сама генерация фикстур | **Скрипт** под `~/.ai/skills/_scripts/de/testing/`, обёрнутый рецептом Justfile; `generate-synthetic-fixtures` — слой суждения над ним. Это та форма, которую `/save-all-deterministic-for-skill-as-scripts` произвёл бы в любом случае — стройте так с самого начала. |
| Обнаружение дрейфа копий навыков | **Хук** — репортер `SessionStart`, уже предложенный в родственном плане. Только отчёт; хук, молча пере-линкующий файлы при старте сессии, — худший баг, чем тот, который он чинит. |

Никаких других новых хуков. Каждый из десяти навыков выше должен запустить
`/save-all-deterministic-for-skill-as-scripts` перед своим sync-gate — обязательно, а не
опционально.

## 4. Честная заметка о стоимости

Десять новых навыков против каталога из 521 навыка — реальный прирост, и сессия, которая их
предлагает, — не та сессия, что их поддерживает. Выше встроены две меры смягчения: **шесть
запрошенных возможностей свёрнуты в переиспользование** и **пять запрошенных dlt-навыков свёрнуты
в один**. Без них буквальное прочтение просьбы производит шестнадцать.

Если когда-либо будет построена только одна волна, стройте **Волну 1** — эти три имеют нулевое
покрытие в каталоге и живого потребителя в OGIP.
