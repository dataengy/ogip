# ADR-0011 — Минимальные секреты: `.env` + секреты GitHub Actions

- **Статус:** Принято
- **Дата:** 2026-07-17
- **Связано с:** D10 · `docs/comparisons/secrets-management.md`

## Контекст

Секреты должны оставаться вне git и работать в CI. Связка «vault + GPG» рассматривалась, но
она избыточна для fork-and-run портфолио-платформы.

## Решение

Выбираем **минимальный, самый лёгкий** стек: *имена* слотов секретов объявляются один раз в
`config/config.yml` (SSoT); **gitignored `.env`**, заполняемый вручную для локального запуска
и VPS; **зашифрованные секреты GitHub Actions** для CI. Никакого vault-демона, никакого GPG,
никакого внешнего аккаунта на пути по умолчанию. **Bitwarden CLI** и **git-secret** остаются
документированными **opt-in** бэкендами.

## Последствия

- Нулевая дополнительная рантайм-зависимость; тривиально запускается тем, кто форкнул проект.
- Никакой автоматической централизованной ротации, пока не включён opt-in бэкенд.

## Рассмотренные альтернативы

- **Связка Bitwarden + секреты GitHub + git-secret** — откатили: избыточно сложно для такого масштаба.
