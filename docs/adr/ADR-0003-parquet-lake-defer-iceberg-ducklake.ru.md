# ADR-0003 — Parquet-озеро; отложить Iceberg/DuckLake

- **Статус:** Принято
- **Дата:** 2026-07-17
- **Связано с:** [ADR-0002](ADR-0002-duckdb-analytical-engine.md) · `docs/comparisons/iceberg-vs-ducklake.md`

## Контекст

Сырому озеру нужен открытый колоночный формат. Табличные форматы (Iceberg, DuckLake) добавляют ACID,
снапшоты и мультидвижковые чтения — но также требуют каталога для эксплуатации.

## Решение

Использовать **обычный Parquet** (через PyArrow) на локальной ФС (по умолчанию в dev) / **Cloudflare R2**
(облако для записи); пути кода на S3-API идентичны (профили MinIO/S3). Табличные форматы остаются
**исследовательским направлением** (`iceberg-vs-ducklake.md`) и внедряются только тогда, когда
конкурентность/машина времени/мультидвижковые чтения становятся продуктовыми требованиями.

## Последствия

- Не нужно эксплуатировать каталог; форкнуть и запустить остаётся тривиальным.
- Нет ACID/машины времени на уровне таблиц до тех пор, пока не запустится задокументированная миграция.

## Рассмотренные альтернативы

- **Iceberg / DuckLake по умолчанию** (ADR-022 из OGAP) — отменено: добавляет каталог и эксплуатационную нагрузку, пока не оправданные.
