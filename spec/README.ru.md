# `spec/` — движко-независимая спецификация данных (SSoT)

Слой спецификации, не зависящий от реализации, — *Open Data Contracts + портируемый SQL*
([ADR-0005](../docs/adr/ADR-0005-spec-ssot-bruin-odcs-compiler.md)). Движки исполнения
**потребляют** его; они никогда его не переопределяют. Для *чтения* `spec/` не требуется ни
один бинарь движка.

| Подкаталог | Содержит | Формат |
|---|---|---|
| `contracts/<source>/` | контракты данных источников (схема · качество · SLA · владение) | **ODCS** |
| `sql/{staging,core,star,am,marts,fs}/` | портируемые SQL-модели (SQL + инлайновые линеаж/DQ/владение) | формат **Bruin asset** — мигрирует на **`@odts 0.1`** ([ADR-0016](../docs/adr/ADR-0016-odts-authoring-format-spec-sql.md)) |
| `sql/_ext/<engine>/` | редкие движко-специфичные SQL-переопределения | SQL движка |
| `dq/policy.yml` | сквозные правила DQ / серьёзность | YAML |
| `datasets/` | реестр датасетов (метаданные, владение) | YAML |
| `lineage/` | производный граф зависимостей | генерируется |
| `ODTS/` | нормативный профиль ODTS 0.1, руководящий бриф и примеры соответствия | Markdown + SQL |
| `ODOS/` | нормативный профиль ODOS 0.1, схема и примеры соответствия | Markdown + JSON Schema + YAML |

**Компилятор спецификации** (`src/ogip/spec_compile/`) рендерит всё это в нативные для
движков проекты — **SQLMesh** (по умолчанию), dbt, Bruin. _Наполняется в фазе 1; M0
закладывает первые модели RAWG._

Правила авторинга SQL-моделей — формат, макросы, SQL-дисциплина и шлюз, через который
проходит каждое синтаксическое предложение, — живут в [`sql/AGENTS.md`](sql/AGENTS.md).

Каталоги `ODTS/` и `ODOS/` в верхнем регистре описывают сами стандарты. Строчный `sql/` и
планируемый каталог `orchestration/` содержат документы OGIP, соответствующие этим стандартам.
